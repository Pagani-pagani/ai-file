工作階段狀態：—

說明

下載 Windows 端

先在 Windows 電腦上安裝 AI File，設定好允許的資料夾，拿到工作階段代碼再回來登入。

  • 開啟 agent 資料夾（啟動器、主程式、自我檢查）
  • 下載整包 ZIP（ai-file-main.zip）
  • 開啟 GitHub 專案頁面

下載後解壓縮，雙擊「啟動 AI File.bat」就會開始跑（用已簽署的 pythonw.exe 啟動）。

怎麼用

  1. Windows 電腦：下載上面那包，雙擊「啟動 AI File.bat」，照設定精靈貼上 Token（只設定一次，存在電腦裡）、選好允許的資料夾，拿到工作階段代碼。第一次啟動會自動在桌面建立捷徑，也會自動檢查更新。
  2. 管理員第一次要在這個網頁的管理員介面設定一次 GitHub 金鑰（和本地端同一組）。
  3. 把工作階段代碼給 AI（例如 Muse）。AI 在這個頁面點「AI 登入」，輸入名稱和代碼就好，不用再貼 Token。
  4. 你的電腦會跳通知，問你要不要允許連線。按「是」之後，AI 才能暫存檔案。
  5. AI 暫存的檔案會等在中繼 repo。你的電腦一看到待同步，就會跳「立即同步」讓你看過清單，按「同意」才會真的寫進電腦。
  6. 隨時可以按本地端浮動視窗的「停止」，或在這裡的管理員介面按「停止」。停止後 AI 就動不到任何檔案。
  7. 每次同步之前，本地端會先備份受影響的檔案（放在程式資料夾的 ai-file-backup，只留最近 20 批）。想回到同步前的狀態，按浮動視窗的「紀錄」→ 該批的「返回」，或在管理員介面的異動紀錄按「返回」（要等本地端確認）。
  8. 管理員介面裡有「檔案總管」：可以看到允許的資料夾裡所有檔案與資料夾（副檔名、建立時間、大小、種類），電腦開著會顯示即時內容，沒開就顯示上次快照。上傳、編輯、刪除、重新命名都會先暫存，電腦上按「同意」才會真的套用。

安全說明

  • 網頁本身碰不到你的電腦，所有檔案都先暫存在私人中繼 repo，本地端檢查通過、你按同意後才寫入。
  • Token 是 GitHub 細粒度 Token，只授權 ai-file-relay 一個 repo 的內容讀寫，其他 repo 碰不到；隨時可以在 GitHub 設定裡撤銷。
  • 每個檔案都要帶著當下有效的工作階段代碼，重新生成代碼後舊代碼的暫存一律拒收。
  • 任何想寫到允許資料夾以外的路徑，本地端直接拒絕、立刻通知你、寫入紀錄。
  • 管理員密碼只鎖這個瀏覽器的介面，真正的保護是上面三點。
  • 金鑰只存在這個瀏覽器。換瀏覽器、開無痕視窗、或瀏覽器設定成關閉時清除網站資料，都要重新設定一次。
