# AI File v1.4

讓 AI 把檔案直接送到你的 Windows 電腦，不用再自己 git clone 或下載解壓縮。
你全程看得到、隨時能停。

## 架構（誠實版）

GitHub Pages 是靜態網站，沒有伺服器，網頁本身碰不到你的電腦。
所以用 GitHub 當中繼，電腦才是守門員：

- **公開 repo `Pagani-pagani/ai-file`**：這個專案。放網頁版（repo 根目錄的 `index.html`、`app.js`、`style.css`）和 Windows 本地端程式（`agent/`）。裡面不放任何機密資料。
- **私人 repo `Pagani-pagani/ai-file-relay`**：中繼資料，只有本人能存取。放待同步檔案、工作階段、停止旗標、活動紀錄、心跳。
- **網頁版**：`https://pagani-pagani.github.io/ai-file/`（啟用 GitHub Pages 後）。用瀏覽器 localStorage 裡的 Token 呼叫 GitHub API 讀寫中繼 repo。
- **本地端**：Python 程式，只用標準函式庫，不用 pip。`啟動 AI File.bat` 啟動後定時輪詢中繼 repo，只在你按「同意」後才把檔案寫進允許的資料夾。

## 安全模型

- 電腦是守門員：網頁永遠不能直接碰電腦檔案；所有檔案先暫存在中繼 repo，本地端檢查通過、你按同意後才寫入。
- GitHub 金鑰 = 一組細粒度 Token（fine-grained PAT），只授權 `ai-file-relay` 這一個私人 repo 的內容讀寫，其他 repo 完全碰不到；隨時可以在 GitHub 設定裡撤銷。金鑰只設定一次：本地端設定精靈貼一次、網頁版管理員介面設定一次，之後再也不用貼。絕對不要把金鑰給 AI。
- 工作階段代碼 = 本地端產生的短代碼（例如 `A1B2-C3D4`）。給 AI 的只有這組短短的代碼。暫存的檔案一定要帶著當下有效的代碼，本地端才會收；重新生成代碼後，舊代碼的暫存一律拒收。
- 管理員密碼只是瀏覽器本機的介面鎖（存在該瀏覽器 localStorage 的雜湊值），不是伺服器驗證；真正的保護是上面三點。
- 路徑守門：每一個檔案路徑解析後必須落在允許的資料夾內，否則拒絕並立刻通知你。
- 停止：本地端浮動視窗的停止鈕或網頁版的停止，都會寫入停止旗標；本地端看到旗標就停手，網頁版也拒絕新的暫存。

## 安裝（Windows 電腦）

1. 下載整包 ZIP：https://codeload.github.com/Pagani-pagani/ai-file/zip/refs/heads/main
   （或到 https://github.com/Pagani-pagani/ai-file 開 `agent/` 資料夾下載）
2. 解壓縮，雙擊 `agent/啟動 AI File.bat`（用已簽署的 pythonw.exe 啟動，不跳黑視窗）。
   備援：雙擊 `agent/啟動 AI File.vbs`。
3. 第一次會開設定精靈：
   - 貼上 GitHub 細粒度 Token（產生方式見下一節）。這組金鑰只設定一次，存在你的電腦，絕對不要把這組給 AI。
   - 選擇「允許 Muse 使用的資料夾」（Muse 只能動這個資料夾裡的檔案）
   - 記下工作階段代碼（例如 `A1B2-C3D4`），把這組給 Muse。給 AI 的只有這組代碼。
   - 存檔後會立刻測試一次連線，失敗會直接告訴你原因（Token 不對／權限不夠／找不到 repo／連不上）。
4. 之後每次開機只要雙擊桌面上的 `AI File` 捷徑就好（第一次啟動會自動建立；浮動視窗裡也有「建立桌面捷徑」按鈕）。每次啟動會自動檢查更新，有新版就問你要不要更新。

## 產生 GitHub 細粒度 Token（PAT）

1. 到 GitHub → 右上角頭像 → Settings → 左邊最下面 Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
2. Token name：`AI File`；Expiration：照你習慣選（建議 90 天或 1 年）。
3. Repository access：選 **Only select repositories**，只勾 `ai-file-relay`。
4. Repository permissions：把 **Contents** 設為 **Read and write**，其他全部不動。
5. 點 Generate token，複製起來（只會顯示一次）。把這組 Token 貼進本地端設定精靈，也在網頁版管理員介面設定一次（兩個地方各設定一次，之後就不用再貼）。絕對不要把 Token 貼給 AI；給 AI 的只有工作階段代碼。
6. 不想用了就到同一個頁面按 Revoke，Token 立刻失效。

## 使用流程

1. 電腦：啟動 AI File，拿到工作階段代碼，把代碼給 Muse（只要代碼，不要給 Token）。
2. Muse：到網頁版點「AI 登入」，輸入名稱和工作階段代碼。
3. 你的電腦跳通知問要不要允許連線，按「是」。
4. Muse 在網頁版上傳或貼上檔案內容、填好相對路徑，按「暫存」。
5. 你的電腦跳「立即同步」通知，看過變更清單，按「同意」才會寫進電腦。
   電腦關機時，暫存就等在中繼 repo；Muse 可以繼續在網頁上工作，等你開電腦再同步。
6. 浮動視窗會逐條列出 Muse 動了哪些檔案。隨時按「停止」，Muse 就動不到了。

## 網頁版管理員介面

打開網站先看到兩張大卡片：左邊「我是 AI」、右邊「我是管理員」，點了才進登入畫面。連線狀態要登入後才會出現；登出按鈕在頁面最下方。右上角的「說明」按鈕打開下載連結與使用說明。

管理員登入後可以看到：

- GitHub 金鑰設定（只設定一次，設定後只顯示「已設定／未設定」，不會顯示金鑰內容；旁邊有「清除金鑰」按鈕。金鑰只存在這個瀏覽器，換瀏覽器、開無痕視窗、或瀏覽器設定成關閉時清除網站資料，都要重新設定一次）
- 連線狀態（讀心跳，每 30 秒更新；過期就是未連線）＋「測試連線」按鈕（失敗會顯示實際原因）
- 允許的資料夾、工作階段代碼、重新生成代碼
- 停止 / 恢復
- 待同步清單（每筆旁邊有「取消暫存」，按了就從待同步清單移除，檔案型的暫存檔也會一起刪掉）
- 檔案總管：可以看到允許的資料夾裡所有檔案與資料夾（名稱、副檔名、建立時間、大小、種類）。電腦開著會顯示即時內容，沒開就顯示上次的快照。上面有「搜尋檔案」（整個資料夾遞迴搜尋）、麵包屑導覽、「重新整理」、「上傳新檔案」、「多選」。點資料夾進入；檔案快按兩下（手機按「⋯」）開操作選單：下載、編輯（文字檔、200KB 以下）、刪除、多選；資料夾的操作選單是重新命名、刪除（會先告訴你裡面有幾個檔案）。多選後按「確認」可以一次刪除或一次重新命名好幾個。所有操作都會先暫存，電腦上按「同意」才會真的套用。
- 過去所有異動紀錄（同一批同步整理成一組，每組旁邊有「返回」按鈕，按了會等本地端確認再還原）

AI 登入後只看到 AI 介面：暫存檔案、上傳／貼上內容、要求刪除，以及「我暫存的檔案」（每筆旁邊有「取消暫存」，只能取消自己的項目）。

## 備份與返回

每次同步之前，本地端會先把所有受影響檔案的「目前內容」備份起來，放在程式資料夾的 `ai-file-backup/<批次 id>/`（絕對不要放在允許的資料夾裡）。每批同步寫一筆紀錄到本機 `ai-file-history.json`（批次 id、時間、AI 名稱、每筆路徑／動作／備份路徑），只留最近 20 批，舊的備份資料夾自動清掉。

想回到同步前的狀態，有兩種方式：

- 電腦端：浮動視窗按「紀錄」，由新到舊列出每一批，按該批的「返回」，確認後就還原（被改過／刪掉的檔案從備份還原，被新增的檔案刪掉）。一批只能返回一次，返回過的按鈕會變成「已返回」。
- 網頁版：管理員介面的異動紀錄裡，每批旁邊按「返回」，會先顯示「已送出，等本地端確認」；你的電腦會跳出確認對話框，你按確定才真的還原。

## 快照與檔案總管

本地端每次打開（啟動完成後），以及每次同步、返回、重新命名完成後，都會對允許的資料夾做一次「快照」，寫到中繼的 `snapshot.json`。快照是清單，不是檔案內容：每筆有相對路徑、是檔案還是資料夾、大小、建立時間、副檔名、種類（圖片／文件／試算表／簡報／影片／音樂／壓縮檔／程式／其他）。最多列 2000 筆，超過會在網頁上顯示「檔案太多，只顯示前 2000 筆」。

網頁版管理員介面的「檔案總管」就是在看這份快照：

- 電腦開著：打開檔案總管或按「重新整理」時，網頁會請電腦立刻重新產生快照（最多等 30 秒），看到「即時」就表示是剛產生的；超過 30 秒沒回應會顯示「電腦沒回應，可能沒開」，先看上次的快照。
- 電腦沒開：顯示上次快照，旁邊標著快照時間；刪除／變更／重新命名都先暫存起來，等電腦開了、你按「同意」才套用。
- 下載和編輯文字檔時，網頁會向電腦索取檔案內容（10 MB 以下才行）；電腦沒開就顯示「電腦沒開，無法讀取檔案內容」。
- 停止旗標開啟時，檔案總管只能看快照和重新整理，不能下載／編輯／暫存任何變更，要先按「恢復」。

注意：管理員在檔案總管暫存的項目不用等工作階段核准（那是你本人在操作），但一樣要經過停止旗標檢查，一樣要等電腦上按「同意」才會真的套用。

## 本機資料在哪裡

本地端資料都在程式資料夾（`agent/` 資料夾，`ai_file_agent.py` 旁邊）：

- `ai-file-config.json`：GitHub Token、允許的資料夾、工作階段代碼。
- `ai-file-log.txt`：本機紀錄。
- `ai-file-history.json`：同步紀錄（只留最近 20 批）。
- `ai-file-backup/`：同步前的檔案備份（只留最近 20 批）。

桌面捷徑只是 Desktop 上的一個 `AI File.lnk`。沒有寫登錄檔、沒有寫 AppData。

想全部重設：在浮動視窗按「重設資料」，確認後會刪除上面四個檔案與備份資料夾，然後重新打開第一次設定精靈。

浮動視窗按右上角 X 只是把視窗隱藏，程式還在背景跑；要真正結束請按浮動視窗裡的「結束程式」按鈕。

## 已知限制（照實說）

- GitHub Pages 沒有伺服器，「即時」其實是輪詢（即時模式每 5 秒、心跳每 30 秒），不是真正的即時推播。
- 檔案要經過 GitHub 中繼 repo：單檔建議 1 MB 以下（Contents API 限制），不適合傳幾百 MB 的大檔。
- Token 要你在 GitHub 設定裡親手產生一次，Muse 不能代勞。
- 桌面捷徑建立（WScript.Shell）、自動更新下載、Windows 桌面通知無法在 Linux 上實測。
- 連不上中繼時，自我檢查第 10 步和浮動視窗的「連線狀態」會直接顯示原因（401 Token 不對／403 權限不夠／404 找不到 repo／連不上網路），請先照原因處理。
- 管理員密碼只鎖瀏覽器介面；真正的保護是 Token 範圍＋工作階段代碼＋本地端守門。
- 同一時間如果兩邊同時寫 activity.json，後寫的可能蓋掉先寫的（v1 已知限制，檔案小、頻率低，實務上很少發生）。
- 快照的建立時間在 Windows 上是真正的建立時間，在 Linux 上是檔案最後被改動的時間（Linux 沒有另外存建立時間）。
- 檔案總管的編輯只支援文字檔（txt／md／json／js／py／html／css／csv／log／xml／ini／bat／ps1，200KB 以下）；其他檔案請下載後修改再上傳覆蓋。
